# Release v0.7.0

## Overview

v0.7.0 is a **decoupling and tooling** release. 

Two couplings are cut:

- On the backend, every plugin runtime — Gateway, MCP, and Worker —
now loads each plugin through a private module registry and gives it a per-plugin context: plugins still run together in one host process, but each
imports its own config where it needs it (`require('@tetherto/mdk-<host>/plugin')`), and each sees only what the host puts in its context. This
deprecates the host injecting a `services` object.
- On the frontend, the mining Gateway's vocabulary: device tags, aggregate field names, Mongo selectors, query keys and factories, moves out of
`@tetherto/mdk-ui-foundation`'s root barrel into a preset, so that what remains is a promise that works against any API

The tooling provides three new packages:

- **`@tetherto/mdk-cli`** gives the stack a front door: `mdk onboard` writes a spec, `mdk create` scaffolds workers, gateway plugins and a dashboard
  into it, and `mdk run` boots the lot; the dashboard is a standalone Vite/React app scaffolded from `examples/mdk-ui-shell-template` and run with
  `npm run dev`, independent of the separate `@tetherto/mdk-ui-cli` (`mdk-ui`) tooling
- **`@tetherto/mdk-agent`** is a conversational operator agent that runs a local model, calls fleet tools over MCP and stops for human approval before
  any write
- **`@tetherto/mdk-plugin-agent`** is how that agent is deployed behind the Gateway — an SSE (Server-Sent Events) chat API that comes with enabling
  the agent, not a separate product to adopt

Separately, a new performance and scalability benchmark harness boots a real multi-process fleet, drives load, runs failure drills, and fills in the
deployment-sizing template from measurements rather than by hand.

For the detailed, itemized list, see the [v0.7.0 changelog](../../../CHANGELOG.md).

## Breaking changes

- **Gateway plugins receive a per-plugin context, not injected services.** Handlers drop the `services` argument and read config from
  `require('@tetherto/mdk-gateway/plugin')`; a plugin needing Kernel access builds its own client. Migration steps in the changelog.
- **The Gateway's Kernel data proxy is gone.** The Gateway keeps no Kernel connection of its own — plugins talk to the Kernel and the Gateway
  aggregates — and telemetry history is served from the Workers that own it. MCP plugins get the same per-plugin context.
- **`createMcpServer` changed.** It takes `{ kernelKey, kernelBootstrap }` instead of a pre-built client, and tool handlers drop their `services` argument
- **`createMdkClient` is auto-connecting.** Its methods connect on first use, so there is no `connect()` step; the former explicit-transport signature
  is renamed **`createRawMdkClient`** and still exported.
- **A Worker Plugin is now a package directory.** `WorkerRuntimeV2` points at a directory whose `mdk-contract.json` declares each handler by path, and
  handlers read their device from `require('@tetherto/mdk-worker/device')`. `WorkerRuntime` (v1) is unchanged and still exported.
- **The mining preset moved to `@tetherto/mdk-ui-foundation/presets/mining`.** The dialect, query keys and mining factories left the root and
  `./query` barrels; nothing was renamed, so the fix is the import specifier only.
- **`Alerts` and `CurrentAlerts` take a flat `Device[]`**, not `Device[][]`, and `useCurrentAlertDevices` resolves a flat list — pass rows straight
  through.
- **Header preference keys and one stats field were renamed** off the legacy reference-app codename: `mosMiners`/`mosHashrate` →
  `appMiners`/`appHashrate`, and `SiteMinerStats.mosTotal` → `appTotal`. Stored preferences merge over the defaults, so old keys fall back rather than
  leaving the toggles undefined.
- **`VITE_MDK_API_URL` supersedes `VITE_API_BASE_URL`.** The old name still reads for one more major and warns once per process; the `VITE_MDK_`
  prefix keeps MDK from silently reading a host app's own `API_BASE_URL`.

## What's new

- **`@tetherto/mdk-cli`**: the `mdk` command-line tool — `onboard` writes `mdk.yaml`, `create worker` / `plugin` / `dashboard` scaffold into a
  role-grouped layout, `run` boots the stack (or one component), and `status` reports health with scriptable exit codes
- **`@tetherto/mdk-agent`**: a conversational operator agent that runs a local model and calls fleet tools over MCP — nothing leaves the machine, and
  writes stop for human approval. It ships a tool-authoring contract, a pluggable session store, and an eval battery that scores against the live
  fleet.
- **`@tetherto/mdk-plugin-agent`**: the agent behind the Gateway — chat sessions, SSE message streams, and approval round-trips; with no auth plugin
  present it serves a single `local` operator
- **Auto-generated MCP tools from Gateway plugins**: mark a plugin dir `autoGenerateMcp: true` and its HTTP routes become MCP tools with no second
  manifest — no more hand-building a tool per endpoint
- **A replaceable `AuthProvider` in the UI**: one object describing the whole session — token source, sign-in, refresh, sign-out, roles — taken as an
  `MdkProvider` prop and published through `useMdkAuth()`. Ships `bearerTokenAuth()`, `noAuth()`, and the Gateway's own `gatewayRedirectAuth()`.
- **An injectable data source**: `createMdkQueryClient` repoints the mining factories and the adapter hooks above them at another API, and
  `createResourceQuery` / `createResourceMutation` declare new resources from an endpoint plus a few mapping rules.
- **A built-in `health` telemetry channel** on every `WorkerRuntimeV2` device, plus `pullWorkerTelemetry(workerId, query)` for worker-scoped aggregate
  queries
- **A performance and scalability benchmark harness** that boots a real multi-process fleet, drives load, runs failure drills, and writes a filled
  sizing profile plus a comparison matrix
- **Two new build gates** in `fullcheck`: `check:api-surface` diffs both consumer-facing packages' exported names against a committed baseline, and
  `check:byob` keeps the bring-your-own-backend demo off MDK's data layer

## Changed

- Built-in Gateway plugins moved onto the per-plugin context and own their Kernel clients, connecting lazily so a missing Kernel degrades per request
  rather than at boot
- Telemetry history is sourced from the Workers' own stat and log stores, with the store-era `*_aggr` field names aliased onto their base stat fields
- The skill suite renamed `mdk-device-worker` → `mdk-worker-plugin` and replaced `mdk-app-plugin` with a fuller `mdk-gateway-plugin`, and
  `@tetherto/mdk-skill` gained a programmatic entry point that `mdk skill add` uses

## Removed

- The Gateway's Kernel data proxy — the `dataProxy`, `isRpcMode` and the in-process Kernel handle
- The sample worker's `plugin/` module tree, superseded by the contract-plus-`src/` layout
- The `mdk-app-plugin` skill, superseded by `mdk-gateway-plugin`

## Fixed

- **Dashboard read hooks fetched while signed out**: Would clear the auth store and bounce a user out of a half-finished sign-in flow; all are
  now gated on a session
- **List hooks returned rows from only the first responding Kernel**: a rack-sharded deployment silently lost every node after the first; the rows
  are now flattened
- **The devkit's line-chart example built its x-axis in seconds** where the chart divides by 1000 itself, landing every point in January 1970

## Security

- **`brace-expansion` raised to `>= 5.0.9`.** The existing `>= 5.0.7` pin satisfied one advisory but a second bypasses that mitigation; the override selectors move to `>= 5.0.9` and widen so the 5.0.7 and 5.0.8 copies already in the tree are caught. Everything dedupes to a single copy.
- **`undici` and `fast-uri` high advisories cleared**, both resolving from the existing overrides once the lockfiles were regenerated; the `fast-uri` selectors are now split per major and applied consistently across the root, [`ui/`](../../../ui/README.md), the Gateway and the MCP server.
- **`js-yaml` pinned to `4.3.1`** in place of an open range that let a fresh install drift, and **`@hono/node-server` pinned to `2.0.12`** at the root to match the MCP server.
- A dependency-audit sweep regenerated every backend package lockfile against these overrides.

Worth knowing: the UI audit job runs on pull requests only, so the default branch is never audited and an advisory published mid-cycle surfaces on every open PR at once, rather than on the branch that introduced it.
