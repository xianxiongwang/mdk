# Release v0.6.0

## Overview

v0.6.0 is a **subtraction and agent-tooling** release. Its centre of gravity is the Gateway: the entire built-in HTTP API — auth and OAuth2, WebSocket, alerts, users, the audit log, and roughly twenty route/handler/schema modules — is deleted, leaving a thin plugin host that serves only what plugins declare. In its place the MDK grows agent-facing surface: a new `@tetherto/mdk-mcp` package serving MDK data over the Model Context Protocol, and `@tetherto/mdk-skill`, an Agent Skills bundle assembled from the monorepo's own artifacts.

This rebuilds the developer experience. The UI shell template became a runnable example rather than a scaffold buried in the CLI, and `mdk-ui create` now hands you a bare backbone whose feature pages you add on demand. The examples collapsed into a single [`examples/mvp-site`](../../../examples/mvp-site/README.md) single-container site, the repo root became an npm workspaces monorepo, and Whatsminer learned to speak both v2 and v3 of the vendor API.

For the detailed, itemised list, see the [v0.6.0 changelog](../../../CHANGELOG.md).

## Breaking changes

- **The Gateway no longer has an API of its own.** Every built-in route module and its supporting libraries are gone, along with the auth/OAuth2 facilities, the WebSocket plugin and alerts broadcast loop, the global-data hyperbee, and the audit logger. Routes now come exclusively from plugins — `telemetry`, `site-hashrate`, and the new `site-monitor` are registered by default, and anything else you need you supply via `extraPluginDirs`. Eleven dependencies were dropped and `@tetherto/svc-facs-httpd` moved v1.0.0 → v2.0.0.
- **The bundled auth plugin is unwired.** `@tetherto/mdk-plugin-auth` still ships, but the Gateway neither registers it nor provides the `authLib` service its controllers depend on. Plan to bring your own identity layer.
- **`startGateway()` lost its auth options**: `opts.noAuth`, `opts.auth`, and `opts.httpdOauth2` are removed, and `auth.config.json` / `httpd-oauth2.config.json` are no longer written into the run directory. `startKernel()` is now a thin alias for `getKernel()`.
- **`@tetherto/mdk-mock-control-service` is removed.** The mock control agent now lives in `@tetherto/mdk-worker-mock`, replacing nine duplicated per-worker copies
- **`mdk-ui create` scaffolds a bare backbone.** You get Google OAuth sign-in, the token lifecycle, and the app frame around a Home page — no feature pages. Dashboard, Alerts, Pool Manager, Explorer, and Site Overview are managed pages you add with `mdk-ui add page <Name>`. The template itself moved out of the CLI package to [`examples/mdk-ui-shell-template/`](../../../examples/mdk-ui-shell-template/README.md).
- **Examples restructured**: `examples/e2e/` and `examples/site-backend/` are gone (folded into [`examples/mvp-site/`](../../../examples/mvp-site/README.md)), and [`examples/backend/`](../../../examples/backend/README.md) was de-packaged — its nested `package.json` files removed, leaving plain runnable scripts
- **Header stat box prop renames.** `HeaderHashrateBox` and `HeaderMinersBox` props renamed from MOS terminology to App terminology: `mosPhs` → `appPhs`, `mosTotal` → `appTotal`, `mosLabel` → `appLabel` (default changed from `'MOS'` to `'APP'`). Update component usage to use the new prop names.

## What's new

- **`@tetherto/mdk-mcp`**: An MCP server exposing MDK data to agents as declarative tools. Tools are declared in `mcp-plugin.json` manifests with optional JSON-Schema argument validation, receive the MDK protocol client via injected services, and are served over Streamable HTTP on loopback
- **`@tetherto/mdk-skill`**: The MDK Developer Skill Suite: five Agent Skills (`mdk`, `mdk-device-worker`, `mdk-app-plugin`, `mdk-deployment`, `mdk-ui-component`) with architecture, protocol, glossary, and contract-authoring references, a contract JSON Schema, and contract-validation and worker-smoke scripts. Installs flat into `.cursor/skills/` or `.claude/skills/`
- **`site-monitor` Gateway plugin**: Read-only site identity (`GET /auth/site`), feature configuration (`GET /auth/featureConfig`), and live per-device hashrate with site totals (`GET /site-monitor/hashrate`)
- **Whatsminer v2 + v3 API support**: A protocol-handler layer that resolves the right handler from any version string by major version, covering v2 (port 4028) and v3 (port 4433) with automatic command translation between the two command styles
- **[`examples/mvp-site`](../../../examples/mvp-site/README.md)**: A minimal single-container site: Kernel, Gateway, a Whatsminer worker, an Ocean pool worker, a SATEC powermeter, the React UI, and an MCP server, deployable under PM2 and seeded from a local device config
- **UI additions**: A `ContainerDetail` page shell with a per-model tab strip, a `useSystemInfo` hook composing three read-only Gateway reads into one page-ready payload, keyboard-accessible clickable rows on the `DataTable` primitive and device explorer, and exported hashrate-formatting helpers
- **Container worker guides**: Antspace and Bitdeer, plus new Kernel-modules and protocol-messages reference pages

## Changed

- **The repo root is an npm workspaces monorepo.** Twenty-one members (backend core, every worker, and [`examples/mvp-site`](../../../examples/mvp-site/README.md)) install with a single `npm ci` at the root; [`ui/`](../../../ui/README.md) and the example UIs stay standalone. CI resolves which mode applies per package, so members correctly link their dev binaries
- The Gateway consumes `@tetherto/mdk-client` and `@tetherto/mdk-plugins` as `^0.6.0` registry ranges instead of `file:` links
- Doc generators extract TypeScript types through a shared ts-morph utility
- All packages are synced to `0.6.0`, including the shell template, which leaves its `0.0.0` scaffold default

## Removed

- The Gateway's built-in HTTP API surface, and the roughly forty unit suites plus WebSocket integration test that covered it
- `@tetherto/mdk-mock-control-service` and the nine per-worker mock-control-agent duplicates
- `examples/e2e/`, `examples/site-backend/`, and the nested packages under [`examples/backend/`](../../../examples/backend/README.md)
- The `mdk-ui-shell` template tree inside the CLI, the `generate:shell` script, and the Gateway's `test:ws` script

## Fixed

- **Device actions no longer fail with a 400.** Staged actions were posting client-only targeting fields the voting endpoint does not accept while omitting the required `query`. Targeting is now derived into `query` from the staged tags, with an opt-out for actions that target by device id.
- **A single bad pool account no longer aborts an Ocean stats cycle.** Unknown or inactive accounts are logged and skipped instead of failing the whole fetch.

## Security

- **`react-router-dom` → `react-router` v8.** `react-router-dom@7` carries a high-severity advisory whose only fix landed in `react-router@8.3.0`, a release that discontinued the `react-router-dom` package outright; so no override could resolve it. The catalog app, the shell template, and both example UIs now depend on `react-router@^8.3.0` and import from `react-router`. No router API changed (v7's `react-router-dom` was already a re-export), but **apps scaffolded from an earlier template must swap the dependency and the import specifier**, and `react-router@8` raises its peers to `react`/`react-dom` `>= 19.2.7` and `engines.node` to `>= 22.22.0`. The devkit, adapter, and foundation packages declare no router dependency and are unaffected.

  **Migrating an app scaffolded before 0.6.0:**

  1. Confirm `node --version` is `>= 22.22.0`, and `react`/`react-dom` are `>= 19.2.7`; upgrade first if not.
  2. In `package.json`, replace the `react-router-dom` dependency with `react-router@^8.3.0`.
  3. Replace every `from 'react-router-dom'` import with `from 'react-router'`. No router API changed, so no other code edits are needed.
  4. Run `npm install`, then `npm run typecheck` and `npm run test` to confirm the swap.

  The bundled `starter` CLI template intentionally stays on `react-router-dom@^6`, which this advisory doesn't affect; don't migrate apps scaffolded from it.
- **`ajv` `8.17.1` → `8.20.0`** in [`backend/workers`](../../../backend/workers/README.md), clearing a ReDoS advisory
- **`brace-expansion` forced to `>= 5.0.8`** across the root, [`ui/`](../../../ui/README.md), [`backend/core`](../../../backend/core/README.md), [`backend/workers`](../../../backend/workers/README.md), and two examples. One residual path remains, reachable only through the dev-only `standard` → eslint 8 → minimatch 3 chain, for which upstream never published a patched 1.x; it is documented in the `audit-ci` allowlist with the reasoning rather than silently suppressed
- Removed a dead override pinning `@isaacs/brace-expansion` to a version that was never published
- Further overrides clear advisories in `immutable`, `js-yaml`, `linkify-it`, `shell-quote`, `ws`, `@hono/node-server`, and `svgo`; `fastify` and `@fastify/static` were bumped alongside them
